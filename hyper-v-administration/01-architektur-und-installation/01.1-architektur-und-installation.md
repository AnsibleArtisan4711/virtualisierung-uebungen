## Lernziele

Nach dieser Übung kannst du

- den architektonischen Unterschied zwischen Typ-1- (Bare-Metal) und Typ-2-Hypervisoren sowie die Rolle der Parent Partition und der Child Partitions in Hyper-V erklären
- Hardware- und Firmware-Voraussetzungen (SLAT, VT-x/AMD-V, DEP/NX-Bit) mittels Diagnosewerkzeugen vor der Installation überprüfen
- die Hyper-V-Rolle samt Verwaltungswerkzeugen über den Server Manager und per PowerShell installieren sowie die Grundeinstellungen des Hosts konfigurieren

## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| **Hypervisor** | Schicht zwischen Hardware und Betriebssystemen, die Prozessor und Speicher an Partitionen verteilt |
| **Parent Partition** | Root-Partition mit Windows; führt den Virtualisierungs-Stack aus und hat direkten Zugriff auf Hardware-Geräte |
| **Child Partition** | Partition einer VM; sieht nur virtuelle Geräte |
| **VMBus** | logischer Kommunikationskanal zwischen Parent und Child Partition |
| **VSP / VSC** | Virtualization Service Provider (Parent) und Consumer (Gast) für Geräteanfragen über den VMBus |
| **SLAT** | Second Level Address Translation: hardwarebeschleunigte Adressübersetzung (Intel EPT, AMD RVI) |
| **Desktop Experience / Server Core** | Installationsoptionen von Windows Server mit bzw. ohne grafische Oberfläche |
| **`vmms`** | Systemdienst „Hyper-V-Verwaltung für virtuelle Computer“ |

## Aufgabe

### Aufgabe 1 – Überprüfung der Hardware-Voraussetzungen (Einheit 1.1, Einheit 1.2)

Öffnen Sie auf dem Basishost `HV-HOST01` eine administrative Eingabeaufforderung bzw. PowerShell. Prüfen Sie mithilfe von `systeminfo.exe` die Anforderungen unter den Hyper-V-Anforderungen (oder das Vorhandensein eines bereits laufenden Hypervisors). Dokumentieren Sie die Ausgabe.

### Aufgabe 2 – Installation der Hyper-V-Rolle per PowerShell (Einheit 1.3, Einheit 1.4)

Installieren Sie auf `HV-HOST01` (sofern noch nicht aktiv) die Rolle `Hyper-V` inklusive der Verwaltungswerkzeuge mit dem Cmdlet `Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart` bzw. überprüfen Sie bei vorinstalliertem Host den Status mit `Get-WindowsFeature -Name Hyper-V*`.

### Aufgabe 3 – Konfiguration der Standardpfade und Host-Optionen (Einheit 1.4, Einheit 1.5)

Legen Sie auf `HV-HOST01` die Ordnerstruktur `C:\HyperV\VMs` (für Konfigurationsdateien) und `C:\HyperV\VHDs` (für virtuelle Festplatten) an. Passen Sie in den Hyper-V-Einstellungen von `HV-HOST01` die Standardpfade auf diese beiden Verzeichnisse an und aktivieren Sie die Richtlinie für den Erweiterten Sitzungsmodus (Enhanced Session Mode). Prüfen Sie anschließend den Dienststatus von `vmms` (Hyper-V-Verwaltung für virtuelle Computer).

## Hinweise

- Ist der Basishost selbst eine VM, muss deren Hypervisor die Virtualisierungserweiterungen durchreichen (siehe Modul 08); `systeminfo.exe` zeigt dann unter Umständen statt der vier Werte einen Hinweis auf einen bereits erkannten Hypervisor (Verhalten nach meinem Kenntnisstand, nicht geprüft).
- Nach `Install-WindowsFeature … -Restart` startet der Host neu; vorher offene Arbeit speichern.
- Die Einheiten 1.1 und 1.3 sind Theorie; sie werden über die Kontrollfragen und das Dokumentieren der Befunde erarbeitet.
- Den Ordner `C:\HyperV` nicht im Repository ablegen; er enthält später große Dateien.

## Kontrollfragen

3. Welcher Systemdienst steuert die Verwaltung der virtuellen Maschinen auf einem Hyper-V-Host, und was passiert mit bereits laufenden VMs, wenn dieser Dienst neu gestartet wird?
4. Warum sollten die Standardpfade für virtuelle Festplatten und VM-Konfigurationsdateien vor dem Anlegen der ersten VM angepasst werden?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

**Aufgabe 1 (Überprüfung der Hardware-Voraussetzungen).** Ausführen und dokumentieren (Ausgabe in eine Datei umleiten, **nicht** im Repository ablegen):

```powershell
systeminfo.exe | Out-File C:\HyperV\systeminfo.txt -Encoding UTF8
.\Get-HostPrereq.ps1 -ReportPath C:\HyperV\Prereq.txt
```

Zielzustand: Im Abschnitt „Hyper-V-Anforderungen“ stehen vier Punkte (VM-Monitormoduserweiterungen, in der Firmware aktivierte Virtualisierung, SLAT, DEP); laut Quelle muss jeder Wert „Yes“ sein. Ist der Host eine VM oder läuft schon ein Hypervisor, kann die Ausgabe abweichen – den Befund notieren. Die genaue Ausgabe ist hier **nicht** aufgezeichnet.

**Aufgabe 2 (Installation der Hyper-V-Rolle per PowerShell).** ```powershell
Get-WindowsFeature -Name Hyper-V*
Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart
```

Nach dem Neustart: `Get-WindowsFeature -Name Hyper-V*` zeigt `Hyper-V` und die Verwaltungswerkzeuge als installiert (Install State `Installed`); `Get-Service vmms, vmcompute` zeigt beide Dienste. Zu 1.3: Notiere, welche Edition (Standard oder Datacenter) installiert ist und welche der beiden Installationsoptionen (Desktop Experience, Server Core) – die Lizenzrechte für virtuelle Betriebssysteminstanzen sind **nicht** Teil dieser Übung und im Lizenzvertrag nachzulesen.

**Aufgabe 3 (Konfiguration der Standardpfade und Host-Optionen).** ```powershell
New-Item -ItemType Directory -Path C:\HyperV\VMs, C:\HyperV\VHDs -Force
Set-VMHost -VirtualMachinePath C:\HyperV\VMs -VirtualHardDiskPath C:\HyperV\VHDs -EnableEnhancedSessionMode $true
Get-VMHost | Format-List VirtualMachinePath, VirtualHardDiskPath, EnableEnhancedSessionMode, NumaSpanningEnabled
Get-Service -Name vmms
```

Zielzustand: beide Pfade zeigen auf `C:\HyperV\…`, `EnableEnhancedSessionMode` ist `True`, `vmms` hat den Status `Running`. Die Parameter `-VirtualMachinePath`, `-VirtualHardDiskPath` und `-EnableEnhancedSessionMode` sind in der Referenz zu `Set-VMHost` vermerkt (Quelle); die Eigenschaftsnamen in `Format-List` sind nicht geprüft. NUMA-Spanning: den Wert nur lesen und notieren, nicht ändern (Thema von Modul 05).

**Fragen.** (1) Die Parent Partition (Root Partition) läuft mit Windows, führt den Virtualisierungs-Stack aus, hat direkten Zugriff auf die Hardware-Geräte und erzeugt die Child Partitions. Child Partitions bekommen nur eine virtuelle Sicht (virtuelle Geräte); Geräteanfragen werden über den VMBus bzw. den Hypervisor an die Parent Partition weitergereicht (Quelle: Hyper-V-Architektur). (2) Geprüft werden: SLAT, VM-Monitormoduserweiterungen, in der Firmware aktivierte Virtualisierung und Hardware-DEP (Quelle: Systemanforderungen). SLAT übersetzt Adressen der Gäste in physische Adressen hardwareseitig (Intel EPT, AMD RVI) und entlastet damit den Hypervisor; ab Windows Server 2016 ist SLAT Voraussetzung. (3) Der Dienst heißt `vmms` (Hyper-V-Verwaltung für virtuelle Computer). Was bei seinem Neustart mit laufenden VMs geschieht, ist **nicht geprüft**: nach meinem Kenntnisstand laufen die VMs weiter und sind nur zeitweise nicht verwaltbar. Im Labor mit einer Test-VM beobachten, nie auf einem Produktivhost ausprobieren. (4) Sonst landen die ersten VMs und Festplatten auf dem Systemlaufwerk (Standardpfade, nach meinem Kenntnisstand unter `C:\ProgramData` bzw. `C:\Users\Public`, nicht geprüft); das füllt das Laufwerk und macht ein späteres Verschieben aufwendig. Mit eigenen Pfaden liegt alles an einem dokumentierten Ort.
