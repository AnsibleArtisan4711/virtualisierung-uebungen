## Grundbegriffe

| Begriff | Bedeutung |
|---|---|
| KVM | Kernel-Virtualisierung unter Linux, nutzt CPU-Erweiterungen |
| LXC | Container-Technik unter Linux, teilt den Kernel des Hosts |
| Nested Virtualization | Virtualisierung innerhalb einer virtuellen Maschine |
| vmx/svm | CPU-Merkmale für Intel VT-x bzw. AMD-V |

## Kontrollfragen

1. Wozu braucht Proxmox VE die CPU-Erweiterungen vmx oder svm?
2. Worin unterscheidet sich ein LXC-Container von einer KVM-VM?
3. Warum muss die Virtualisierungserweiterung unter Hyper-V bei ausgeschalteter VM gesetzt werden?
4. Warum sollte der Hostname vor dem Aufbau eines Clusters feststehen?

## Musterlösung

<details>
<summary>Antworten und Zielzustand (erst nach dem Versuch öffnen)</summary>

1. Schema: Hardware → Debian mit Linux-Kernel (KVM) → QEMU-Prozess je VM; LXC nutzt den Host-Kernel; Weboberfläche und Verwaltungsdienste obenauf.
2. Laut Microsoft: VM aus, `Set-VMProcessor -VMName <Name> -ExposeVirtualizationExtensions $true`, MAC-Spoofing am Adapter oder NAT; Fehlerbild: Proxmox meldet fehlende KVM-Hardwarebeschleunigung.
3. Siehe `beispiele/nested_pruefen.ausgabe.txt`: kein vmx/svm, kein `/dev/kvm`; Maßnahme: Erweiterungen am Host-Hypervisor einschalten.
4. Hostname (FQDN) und feste IP sind im Cluster später schwer änderbar; Repository-Wahl und Updates gehören ins Protokoll.

**Kontrollfragen (Antwortskizzen):**

1. Sie ermöglichen Hardware-Beschleunigung für KVM; ohne sie läuft nur Emulation, die für VMs sehr langsam ist.
2. Eine VM hat einen eigenen Kernel und emulierte Hardware; ein Container teilt den Kernel des Hosts und ist leichter, aber weniger stark getrennt.
3. Weil die Einstellung die virtuelle CPU der VM beim Start bestimmt; sie wird laut Microsoft-Dokumentation nur bei ausgeschalteter VM gesetzt.
4. Nach der Dokumentation sollten Hostnamen und IPs vor dem Aufbau festliegen, weil eine spätere Änderung im Cluster aufwendig ist.

</details>
